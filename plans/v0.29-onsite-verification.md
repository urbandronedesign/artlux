# v0.29.0 — what to check on site

> **Status:** Open · **Not a limitation-lift plan** — this folder's usual 10-section template does not
> apply. It is a release-scoped verification note: v0.29.0 shipped with a large part of it never run,
> and this is the list of what to look at, what each failure looks like, and how to back out.

## Why this exists

The editor takes a single-instance lock (`app.requestSingleInstanceLock`, `src/main/index.ts`), so the
CDP harness cannot launch while an operator's own session is open. It was open throughout the session
that built this release. The result: **justify and wrap, the text box, the font picker, per-surface
track stacks, the clip fades, the projector opacity and three framerate fixes carry typecheck, 182
invariants and arithmetic behind them — and no visual pass.**

That is below this repo's normal bar, and it is recorded rather than smoothed over. Merged and released
on the owner's explicit decision to prove it at the venue, which for the projector half is the only
place it *can* be proven: there is no projector and no calibrated output on the dev machine.

## Before leaving

- **Import the fonts.** A named family is whatever the venue machine happens to have; it will
  substitute silently and the wall reads in the wrong face. **Carry it ▸ Import…** copies the file
  into `assets/fonts/` so it travels with the project. This is the one thing that cannot be fixed on
  site. See [TEXT.md](../docs/TEXT.md).
- **Run Collect Assets** once, and read what it reports missing.

## On site, in order of risk

### 1. Surface opacity on a projector — the highest risk in the release

New behaviour: a surface's opacity now reaches the wall. It never did before — it applied to the LEDs,
the 2D stage and the 3D scene, and nothing in the projector path read it.

It rides the master brightness on **three** paths, and the third only exists for calibrated outputs.
The middle one is where brightness had always been identity, and the reasoning for changing that was
*read* (the calibration composer applies no brightness) rather than *seen*.

| Look for | Means |
|---|---|
| A **dark band** at a projector overlap | The blend is being applied twice — the hazard `ProjectorApp`'s own comments warn about |
| One **calibrated** output dimmer than a flat neighbour at the same settings | Opacity or brightness applied on one path and not another |
| A surface at 100% opacity looking **dimmer than v0.28** | The multiply is picking up something it should not |

Quick test: set one surface's opacity to 50% and watch the wall, on a flat output and on a calibrated
one. Then fire a cue that fades a surface out and confirm the light actually leaves.

### 2. Content upside down on a venue mesh

`bitmapFlip.ts` now branches on the **live** renderer rather than compensating unconditionally. If that
reversal is wrong it is wrong for every `ImageBitmap` — so check any mesh textured by a surface. It
hid for two releases because the only bitmaps reaching a 3D plane were shader noise, where a vertical
flip is undetectable. Text makes it obvious in one frame.

### 3. Framerate, with shaders or moving text on screen

Three regressions were introduced and undone in this branch and **none of the fixes were measured**.
The worst: generative sources were silently promoted from the projector pump's ~30 Hz coarse tick to
its ~66 Hz fine tick. Watch the FPS readout with a shader or animated text surface routed to a
projector, and compare against a v0.28 build if anything feels rough.

### 4. The smaller ones

- **Everything faintly dim with no fade set** → the 0.999 threshold in the clip-fade bake.
- **Two outputs showing the same picture, or one black** → per-surface track stacks
  (**Content ▸ Layer**, several ticked).
- **Justified text not reaching both edges**, or a last line stretched → the wrap/justify layout.
- **The font list empty when you click ▾** → the picker reads the machine's fonts on that click; the
  error is shown in place with a retry rather than being swallowed.

## If it is wrong

One command, and it must be a forward revert now that it is public:

```bash
git revert -m 1 081fd17 && git push
```

The branch `scene-scale-and-text` still exists locally. `081fd17` is the merge; `03f46f7` is the
release commit on top of it.

## When the app is next free

Ten minutes with the editor closed clears the whole backlog in one pass — the harness pattern is in
`scripts/capture-docs.cjs` (launch with `ARTLUX_CDP_PORT`, attach with puppeteer-core, back up and
restore `lastProjectPath`). Everything above is a screenshot away; none of it needed a venue except
§1 and §2.
